Changelog

What changed in each release, newest first.

0.3.0 2026-11-25

An assistant you can ask inside Dispatch, and quick edits saved in the order you made them.

  • Assistant (desktop, optional): ask about your requests, scripts and tests inside Dispatch. Connect a model with your own key, or one that runs on this computer. There is none until you add a connection, and your workspace goes to a host that isn’t this computer only after you allow that host.
  • Changes you approve: the assistant can propose edits to requests, scripts, collections and variables. Each shows as a card with what would change; nothing is written until you press Apply, and you can undo it until Dispatch closes. It can’t send or run anything itself; an applied script runs when you send the request.
  • Saving: quick edits land in the order you made them. Before, an older save could finish last and replace a newer one, or bring back something you had just deleted.
  • Secrets and AI assistants: collection variables you marked secret stay hidden whatever their name, and known secrets are hidden in responses, test results and errors that assistants get back.
  • Update notice (desktop): a new version shows in the top bar until you install or dismiss it, and the update check answers sooner on networks where one of the download addresses can’t be reached. Dispatch tells you once before its first check, and you can turn checks off in Settings.

0.2.0 2026-11-24

Extract values into variables, a Secrets section, and cookies for each environment.

  • Extract into variable: select a value in a response and right-click it, or right-click a response header, and save it as a variable. The rule is added to the request's after-response script, so a login refreshes its token on every send, in the runner, in flows and in dispatch-run too. If a response doesn't have the value, or it's empty, the variable keeps the one it had.
  • Secrets section: environments, globals and collections list secret variables in a table of their own, instead of a checkbox on each row. A variable with a name like token or password offers to move there.
  • Cookies per environment (desktop): each environment keeps its own cookies, so a sign-in on staging no longer reaches production. After the update, the cookies you have stay with the environment that was selected; sign in again in the others.
  • Rename in place: double-click a request, folder, collection, flow or environment in the sidebar, or press F2. Enter saves and Esc cancels.
  • Pasting a curl command names the request after its URL, unless you gave it a name of your own.
  • Long header, parameter and variable values wrap while you edit them, and you can drag the name column to resize it.
  • Edits you make while a request, a run or an assistant is still working are kept: a run changes only the variables it set.

0.1.0 2026-11-22

The first release of Dispatch by OGCrafts.

  • Requests: HTTP with params, path variables, headers, every body type (JSON, form-data with files, binary, XML, GraphQL) and auth (Basic, Bearer, Digest, OAuth 2.0, JWT, AWS Signature v4); GraphQL schema tools, WebSocket, MQTT, server-sent events, Socket.IO, and gRPC on desktop.
  • Collections with nested folders, tabs, environments, globals and workspaces; each workspace keeps its own tabs. Undo for every delete, daily local backups, and search across everything (Ctrl+K).
  • A code editor with {{variable}} and dx. completion; pre-request and post-response scripts with tests in a sandbox, with lodash, moment, crypto-js, uuid, ajv and handlebars; 70 fake-data variables.
  • The runner (iterations, delays, CSV or JSON data, JUnit reports), load tests with charts, scheduled runs with notifications, response history with compare, saved examples, generated docs and a local mock server.
  • Flows: wire requests together on a canvas with If, Script, Set variable, For each, Delay and End blocks.
  • Browser login requests that drive Chrome or Edge through a login page and keep the cookies or token as secrets.
  • MCP: test MCP servers (HTTP or a local command, with OAuth sign-in), and let AI assistants on your computer list and send your requests through a local endpoint, with an optional workspace of their own to build requests in. Hand a request to your assistant with a note, let it edit an open workspace only when you allow it, and let it read the console and history if you turn that on; secrets stay hidden from it.
  • Share a request, folder or collection as one self-contained HTML page, with secrets and server addresses left out.
  • Import Postman, OpenAPI 3, Swagger 2, HAR, Insomnia and Bruno; export to Postman; code in 12 languages; paste curl.
  • Workspaces and collections can live in folders of plain files for git (desktop). Keep the folder in OneDrive, Dropbox, iCloud Drive, Syncthing or a git repo to have it on your other computers: changes made there come in on their own, and a file changed in both places is never overwritten; you choose, one file at a time, with the differences shown. Secret values can travel too, opt-in: one file in the folder, encrypted with a passphrase you choose. The dispatch-run CLI runs a workspace folder too, by environment, collection or flow name, with secrets from CI variables or the encrypted file.
  • Secrets encrypted at rest with a device key; client certificates, CA certificates, proxy and a cookie manager on desktop.
  • The desktop app can update itself: Menu, Check for updates. Updates are verified with Dispatch’s signing key before they install.
  • Three looks, each in light and dark: Dispatch (graphite and amber), Grove and Grove classic (Settings, Themes). Right-click menus on tabs and sidebar rows; menus close when you click elsewhere or press Esc.
  • Optional and off by default: anonymous usage counts and error reports, asked once at first launch and changeable any time in Settings. Send feedback from the menu.
  • Menu → About Dispatch shows the version you run and the changes in every release.
  • A one-click Windows setup: double-click, a small window shows the progress, and Dispatch opens. No administrator rights needed; the .msi is there for managed installs.
  • Desktop for Windows, macOS (Intel and Apple silicon) and Linux (x64 and ARM64), the web app, and the dispatch-run command-line runner.
