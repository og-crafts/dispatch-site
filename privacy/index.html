Privacy policy

Last updated 2026-11-25.

Dispatch is built so that we never receive your data: your collections, requests and responses stay with you. If you agree, it sends us a little anonymous information about how it is used and about its own errors. If you add a model to the Dispatch assistant, what you ask it goes to that model, never to us. This page says exactly what.

What Dispatch stores

Your collections, requests, environments, variables, history, cookies, settings and backups. They stay on your device: in your browser’s local storage (IndexedDB) for the web app, in the app’s local storage for the desktop app, and in a folder you choose if you link a workspace or collection to one. We have no server that receives any of it.

Secrets

Secret variables, passwords, tokens, keys, and Authorization and Cookie headers are encrypted before they are saved, using a key that stays on the device and cannot be exported. Exports and backups you download leave secrets out. The same goes for the keys of assistant connections (below).

If you keep a workspace in a folder and turn on Sync secrets, its secret values are also written to that folder, in one file encrypted with a passphrase you choose (AES-256-GCM, key made with PBKDF2). The file goes wherever you keep the folder (your cloud drive or git repository); it never comes to us, and without the passphrase it can’t be read. It is off unless you turn it on.

Requests you send

When you press Send, Dispatch sends that request to the address you typed, with the headers and body you set. Besides that, Dispatch itself only looks for new versions (desktop, described below), sends the reports you opt in to and, from 0.3.0, sends what the Dispatch assistant needs if you have added a connection to it (described below). What the other server does with it is up to that server. Scripts you write can send requests too (dx.send), to the places you tell them to.

A Browser login request opens your installed Chrome or Edge with a new, empty profile that is deleted afterwards, with sync and background networking turned off. It visits the pages in your steps. The values it keeps, such as cookies or a token, are stored as secret variables on this device.

The Dispatch assistant (0.3.0 and later, desktop app)

The desktop app can have an assistant you ask about your own workspace: why a test fails, what a script does, how to write the next one. It is off until you add a connection under Settings, AI assistants. The web app does not have it. Without a connection nothing of it runs and nothing is sent.

Where your questions go. Only to the connection you chose, and only when you ask something:

  • Anthropic: to api.anthropic.com, under your own key.
  • OpenAI: to api.openai.com, under your own key.
  • An address you choose (a gateway, or a server on your network): to exactly that address, with the key you gave it, if any.
  • A model on this computer (for example Ollama at localhost): to your own computer, so nothing leaves it.

Before the first question to a host that is not this computer, Dispatch asks you to allow that host. Changing the scheme, host or port of a connection’s address takes away that permission and its key; changing only its path keeps both. Loading a connection’s list of models and pressing Test contact that host too; the key goes with them, and the test sends a short made-up question, nothing from your workspace. We receive none of this. What the host does with it is up to the host: read its own privacy policy, and note that a model on a server you do not run is somebody else’s server.

What the model can read. What you type, and to answer it, the requests, scripts, names and plain variable values of the workspace you have open, and its environments. The console and past responses only if you tick that for the connection (it is ticked for a model on this computer and not otherwise); the console covers all your workspaces, not only the open one, and the consent question says so. It is also told the name of the open workspace and of the request you have open.

What it can change, and what it cannot. It can propose changes to the requests, scripts and variables of the workspace you have open, one at a time, including deleting a request. (Moving a value into a variable can also add one to your globals, which all workspaces share.) Dispatch shows you each one, and it is made only after you press Apply (or Delete). There is no way to approve changes in advance. The model is then told whether you applied or rejected it. You can undo an applied change until Dispatch closes, as long as it has not changed since; the model is not told that you undid it. The assistant cannot send a request or run anything. What Apply cannot protect you from is what an approved change does later: a script you applied runs when you send that request, and it can read your variables, secret ones included, and send requests of its own; a request whose address you let it change goes to that address. If one of your own schedules sends that request, it will use the change. Dispatch warns about scripts, new addresses, secrets and schedules where it can tell, but it cannot tell everything, so read a change before you apply it.

What is hidden, and what is not. Values Dispatch knows to be secret are replaced by <hidden> before anything leaves your computer: secret variables, tokens, passwords and keys, Authorization and Cookie headers and values, other cookies, sign-ins, client certificate keys and the assistant keys, from every workspace, not just the open one. That is a best effort, and it has limits. Dispatch cannot recognise every secret: one pasted into a plain variable, a URL, a script or a request body under an ordinary name can go to the model. A known secret shorter than six characters is hidden in its own field, but not where the same text turns up somewhere else. Ordinary data is not hidden at all, such as names, e-mail addresses or records in a response the model reads. Do not tick the console option for a host you do not trust, and do not ask the assistant about things you would not send to it.

What is kept on your device. Connection keys are encrypted like other secrets, with a key that stays on the device, are sent only to the connection they belong to, and are never exported or backed up. Chats are kept on this device, encrypted, per workspace (the last 50), and are never in backups, exports, workspace folders or any sync. A chat holds what the model wrote, including the text of the changes it proposed. The cards that show changes, and what Undo needs, are kept in memory only and are gone when Dispatch closes; deleting a chat drops its Undo. The console notes each decision with the name of what it was about. Turn Keep chats on this device off, or press Delete all chats, in Settings, AI assistants; deleting a workspace deletes its chats; removing a connection deletes its key.

We receive nothing from the assistant: no questions, answers, chats, keys or counts. It adds no usage events and no error reports beyond the opt-in ones above.

What Dispatch does not do

  • No account, sign-in or sync.
  • No assistant traffic until you ask it something, or press Test or Load models, with a connection you set up; your workspace goes to a host that is not this computer only after you allow that host; and nothing to us ever.
  • No analytics or error reports unless you opt in (below).
  • No workspace data in update checks. From 0.3.0, the desktop app looks for a new version when it starts and once a day, and when you choose Menu, Check for updates. A notice tells you before the first automatic check, which waits until you restart Dispatch or 24 hours have passed; turn it off there or under Settings, General. Up to 0.2.0, automatic checks are off unless you turn them on. The web app never checks. The check asks GitHub, where the releases are published, for a small file that names the newest version; GitHub sees your IP address, as with any download. Nothing about you or your data is sent, and nothing is installed unless you agree.
  • No advertising and no trackers.
  • No fonts, scripts or images loaded from other sites, in the app or on this website.
  • This website sets no cookies. If you pick a look with the Look menu, your browser keeps that choice in its local storage, on your device only.

Usage and error reports (only if you agree)

The first time you open Dispatch it asks whether to share two things. Both are off unless you tick them, and you can change them any time in Settings, General, Privacy.

  • Anonymous usage, sent to Aptabase (an analytics service built for privacy, EU or US hosting): the name of an action, such as “sent a request”, “imported a file” or “checked for updates”, with fixed labels like the request type (HTTP, gRPC…) or the import format; the Dispatch version, desktop or web, operating system and language; and a random session number that changes every time Dispatch starts. No user id, no cookies, and never your URLs, requests, responses, names, variables or files. See Aptabase’s privacy policy.
  • Error reports, sent to Sentry (error tracking): when Dispatch itself fails, the error message and where in Dispatch’s code it happened, plus the version, operating system and browser engine. Before it leaves your device, Dispatch blanks out web addresses, e-mail and IP addresses, tokens and other long values, and leaves out what led up to the error. See Sentry’s privacy policy.

We use this only to find bugs and decide what to improve, keep it no longer than the services’ standard retention (about 90 days for error reports), and never sell or share it. The services see your IP address when they receive the data, as any server does; we don’t store it.

Feedback

Menu, Send feedback fills in a GitHub issue (public) or an e-mail to us for you to check and send yourself. Dispatch doesn’t send it.

The web app and this website

This website and the web app at dispatch.ogcrafts.cloud/app/ are static files hosted on GitHub Pages. When you open them, GitHub’s servers receive the request for the files and, like any web host, may log your IP address and browser details under GitHub’s privacy statement. We do not receive those logs for individual visitors and we do not add cookies or tracking. After the files load, the web app does its work in your browser.

Your control

To remove everything, delete the data in the app (chats and connection keys under Settings, AI assistants), clear this site’s data in your browser, or uninstall the desktop app and delete any collection folder you created. Nothing is kept by us. Whatever a model host you chose received is kept under that host’s own rules, and only it can delete that.

Children

Dispatch is a developer tool and is not directed at children.
